# 编辑与常驻性能热路径

本轮优化针对实际采样和长文档基准中确认的五条主路径，目标是避免主线程周期性工作、二次方扫描、全文样式与布局，以及同步磁盘 I/O；不改变 Markdown 语义和持久化格式。

## 取舍

1. 刘海位置仍以 30 Hz 轮询，保证悬停与拖入体验；但收起且未按左键时不创建拖拽剪贴板、不查询类型，也不计算拖放区域。只有按键中且拖拽 change count 更新时才检查文件 URL。
2. Markdown 仍在正文变化后解析完整文档，保证跨段代码块和标记配对正确；互斥 token 的包含判断改为合并区间后二分查询，将大量行内 LaTeX 时的热点从二次方降为近似线性。
3. 解析结果可覆盖全文，样式生成与正则扫描必须限定到本次受影响段落。强调样式的 trait 缓冲区也按段落分配，不能再按全文长度分配。
4. TextKit 2 创建、重绘和普通重建只保证可见视口布局。全文 layout 仅保留为显式需求，避免大文档首次展开和每次重绘同步计算全部段落。
5. 自动保存的 JSON 编码、恢复副本和归档写入移到串行后台队列；图片读取、转码、落盘和缓存加载也在独立队列完成。应用退出时显式 flush 两个队列，避免后台任务尚未完成就退出。

## 行为边界

- 图片粘贴先返回稳定的 Markdown 引用，图片完成落盘后通过渲染失效通知刷新编辑器。若后台读取或写入失败，引用会保留为缺图状态，不在粘贴事件中阻塞等待错误结果。
- 标题重命名仍保持同步落盘后再发布 UI 状态，因为它有“失败不发布候选名称”的一致性契约；普通正文自动保存才是完全非阻塞路径。
- 图片缓存使用内存中的 `NSImage`，目前未设置容量上限。笔记图片规模显著增大时，应增加基于成本的淘汰策略。
- Markdown 解析目前仍是全文线性扫描。若单篇笔记增长到多 MB 后仍有输入延迟，应继续做增量 token 化；不能通过缩小解析范围破坏跨段 fenced code block/LaTeX 的正确性。

## 回归约束

- 文件拖拽检查必须先通过“收起、左键按下、change count 更新”三项门控。
- scoped styling 不得生成落在目标段落之外的属性。
- 正文非阻塞 flush 与图片粘贴不得等待注入的慢编码器或慢磁盘 writer。
- 应用和 vendored MarkdownEngine 的完整测试都必须通过；长行内 LaTeX 基准应随文档大小近似线性增长。
